## 로컬 실행
`index.html`과 `asset/`를 같은 폴더 구조로 유지하세요. Python 사용 시 이 폴더에서 `python -m http.server 8080` 후 `http://localhost:8080/`으로 접속합니다. 파일 더블클릭보다 로컬 서버 실행을 권장합니다(캔버스/오디오 브라우저 보안 제한 회피).

## 게임 진행
- Eye Care: 빗 집기 → 왼쪽 눈곱 제거 → 오른쪽 눈곱 제거 → 완료.
- Dental Care: Dental Gel → Edge로 치아 사이 → Soft로 윗니 → 아랫니 → 완료.
- Coat Care: 적시기 → 샴푸 → 거품 → 헹굼 → 타월 → 미스트 → 빗질 → 모인 털 배출.
- Chin Care: 패드 장착 → 클리너 → 패드로 문지르기 → 브러싱.
- Paw Care: Red Honey Balm 집기·넓게 바르기 → Shikonidin 집기·국소 케어.
- 다섯 케어 완료 시 Coco 변신. 각 완료 화면의 구매 버튼은 미국몰로 연결됩니다.

## GitHub·Dropbox 보관 방식

GitHub에는 미국 영어 코드, 한국어 코드, 설정, 문서와 `asset/`의 이미지 37개·오디오 1개를 모두 업로드합니다. 코드가 로컬 상대 경로로 에셋을 참조하므로 폴더 구조를 유지하면 내려받은 뒤 바로 실행할 수 있습니다.

Dropbox는 이미지·오디오 백업용입니다. 일반 Dropbox 공유 링크를 코드의 에셋 경로로 사용하지 않으며, GitHub 또는 배포본의 에셋을 삭제하지 않습니다.

- GitHub: 전체 실행 패키지와 문서
- Dropbox: `asset/images/` 이미지 37개, `asset/audio/` 오디오 1개 백업
- 편집 원본: 별도 파일 없음

파일명이나 `asset/` 폴더 구조를 변경하면 `index.html`과 `ko/index.html`의 참조 경로도 함께 수정해야 합니다. 수정 후 로컬 HTTP 서버에서 미국 영어 `/`와 한국어 `/ko/`를 모두 확인합니다.

## 한국·일본 자사몰에 적용할 경우
- **한국 자사몰:** 함께 보관한 `ko/index.html` 한국어 원본을 사용합니다. 한국어 원본에도 현재 미국몰 상품 링크가 연결되어 있으므로, 모든 케어의 상품 링크를 한국 자사몰의 해당 제품 또는 컬렉션 URL로 교체해야 합니다.
- **일본 자사몰:** 화면 안내, 버튼, 단계명, 완료 메시지, 접근성 설명 등 사용자에게 표시되는 언어를 일본어로 바꾸고, 모든 케어의 상품 링크도 일본 자사몰의 해당 제품 또는 컬렉션 URL로 교체해야 합니다.
- 상품 링크 변경 위치는 각 언어 코드(`index.html`, `ko/index.html`)의 `CARE_PRODUCT_URLS`입니다. 눈·치아·털·턱드름·육구 5개 카테고리를 모두 확인하세요. 일본어 적용 후에는 문구 길이에 따른 줄바꿈과 버튼 배치도 확인하세요.
- 이 최종 보관 폴더에는 미국 영어 코드와 한국어 코드가 모두 포함되어 있습니다. 일본어 코드는 아직 없습니다. 두 언어는 같은 `asset/`의 이미지·오디오를 공유합니다.

## 재배포 주의

- `.openai/hosting.json`은 현재 Site ID를 보존하되 static.directory를 보관본 루트 `.`로 바꿨습니다. 같은 사이트 갱신 목적일 때만 이 ID를 사용하세요. 별도 사이트로 복제할 때는 기존 ID를 그대로 쓰지 마세요.

- 진행 기록 키는 `jayupet-care-progress-us`. 모바일 실기기 전체 완주 검증은 별도 권장합니다.

인증 없이 HTTPS 200 응답을 확인했습니다. 이미지 37개와 오디오 1개의 SHA-256이 모두 배포 원본과 일치합니다. 공개 HTML에는 Cloudflare가 동적으로 삽입한 challenge-platform 보안 스크립트 1개가 있어 전체 HTML 바이트 해시는 다릅니다. 그 서비스 삽입분과 줄바꿈 차이를 제외한 게임 소스는 정확히 일치합니다. 보관본에 호스팅 서비스의 동적 보안 스크립트는 포함하지 않았습니다.

로컬 서버 검증: 보관본의 index.html 및 에셋 38개 모두 HTTP 200, 응답 바이트 일치 확인. 전체 파일 46개(체크섬 파일 포함), 체크섬 기록 45개.

## 한국어 코드 보관 및 검증 범위
- 로컬 서버에서 미국 영어는 `/`, 한국어는 `/ko/`로 실행합니다. `ko/`만 옮기지 말고 공통 `asset/`도 함께 유지하세요.
- 한국어 코드는 보존된 한국어 작업본에서 복사했으며, 에셋 경로만 `../asset/` 구조로 수정했습니다. 한국어 원본 파일과 현재 미국 공개 배포는 변경하지 않았습니다.
- 한국어 원본은 미국 버전에서 추가된 반응형 조정 및 초기화 수정 이전의 작업본입니다. 한국어 코드를 실제 출시하기 전 별도로 화면 크기별 동작과 전체 케어 진행을 검증하세요.
- 공개 배포 URL 및 DEPLOYMENT-VERIFICATION.json의 대조 결과는 미국 버전에 해당합니다. 한국어 코드는 이번 보관본에 추가했으며 공개 배포하지 않았습니다.

## 다음 담당자: 수정·배포 체크리스트

### 인수 및 배포 준비
1. GitHub에서 코드·문서를 받고 Dropbox에서 에셋을 받아 위 폴더 구조로 합칩니다. Dropbox에 보관만 하는 경우에는 코드의 상대 경로를 바꾸지 않습니다.
2. `.gitignore`가 이미지·오디오를 제외하므로 GitHub 저장소만으로 자동 배포하면 에셋이 빠집니다. 배포할 폴더에 이미지 37개와 BGM 1개를 함께 넣거나, 직접 접근 가능한 에셋 URL로 코드를 수정해야 합니다.
3. 전체 폴더를 정적 웹 호스팅의 공개 루트로 사용하면 별도 빌드나 백엔드 없이 실행할 수 있습니다. 미국판 진입점은 `/index.html`, 한국어판은 `/ko/index.html`입니다. 한국어 파일을 루트로 옮기면 `../asset/` 경로도 새 위치에 맞춰 수정하세요.
4. 새 사이트로 배포하는 데 기존 배포 계정은 필요 없습니다. 현재 Sites 사이트를 갱신하려면 해당 계정 권한이 필요합니다. `.openai/hosting.json`은 Sites용 설정이며 다른 호스팅에는 그 서비스의 공개 폴더 설정을 적용하세요.

### 코드·이미지·소리 수정
- 최종 보관본은 유지하고 복사본 또는 Git 브랜치에서 수정합니다. 한국어와 영어는 별도 HTML이므로 공통 기능 수정이 자동으로 양쪽에 적용되지 않습니다.
- 파일명 대소문자와 상대 경로를 정확하게 유지하세요. 이미지 교체 시 투명 배경, 크기와 비율, 도구 끝 위치를 확인합니다. 브러시 접촉 좌표와 캔버스 판정이 이미지에 맞춰져 있어 단순 교체만으로 조작 위치가 달라질 수 있습니다.
- BGM은 `asset/audio/bgm05-new-day-again-255071.mp3`이며 코드의 `BGM_FILE`에서 참조합니다. 효과음은 각 HTML의 Web Audio 코드로 생성하므로 별도 효과음 파일이 없습니다. 오디오 초기화와 사용자 입력 이벤트 연결을 유지하세요.
- 첫 클릭·터치 후 BGM과 효과음이 재생되는지, 음소거·재개가 정상인지 확인합니다. 페이지 진입 직후 자동 재생만으로 판단하지 않습니다.
- 한국몰은 `CARE_PRODUCT_URLS`를 한국몰 주소로 교체합니다. 일본몰은 사용자에게 보이는 언어와 상품 링크 모두 교체합니다. 한국어판에는 미국판의 후속 반응형·초기화 수정도 반영하고 검증해야 합니다.
- 다른 게임 또는 언어판을 같은 도메인에 추가할 때 저장 키가 충돌하지 않도록 확인합니다. 새 진행 상태와 저장된 진행 상태 모두 시험하세요.
- Shopify에 직접 통합할 때는 이미지·오디오 URL과 페이지의 CSS·JavaScript 충돌을 확인합니다. iframe 방식이라면 모바일 높이, 터치 조작, 오디오, 구매 링크 이동도 실제 자사몰 페이지에서 확인하세요.
